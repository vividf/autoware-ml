## 1. 為什麼流水線要這樣拆分

感知（perception）資料集通常很龐大（LiDAR sweep、多視角相機影像），而且每個模型想要的
資料形式都略有不同。此框架把關注點拆成四項，讓每一項都能獨立變化：

| 面向 | 擁有者 | 在哪裡執行 |
| ------- | ----- | ---------- |
| *有哪些 sample 存在＋其 metadata* | `Dataset.get_data_info` | CPU，依需求（on demand） |
| *載入檔案＋做 augment* | `TransformsCompose`（逐 sample） | CPU，在 dataloader worker 中 |
| *把多個 sample 合併成一個 batch* | `DataModule.collate_fn`（`collation_map`） | CPU，worker |
| *以 batch 為單位的 GPU 整形*（voxelize、normalize） | `DataPreprocessing`（模型自有） | GPU，逐 batch |

黃金原則（從總覽文件重複一次，因為這是最容易造成混淆之處）：
**`get_data_info` 回傳的是 metadata，而不是 tensor。** 檔案的載入是在 transform 中進行的。
這讓 dataset 保持簡單，也讓載入方式可以依實驗自由設定。

## 2. `Dataset` — metadata 的來源（`datamodule/base.py:76`）

```python
class Dataset(TorchDataset, ABC):
    def __init__(self, dataset_transforms: TransformsCompose | None = None, **kwargs):
        self.dataset_transforms = dataset_transforms

    def __getitem__(self, index):                                   # :93
        input_dict = self.get_data_info(index)                      # ← metadata dict
        context = PipelineContext(dataset=self, index=index)        # ← orchestration state
        return self.apply_transforms(input_dict, self.dataset_transforms, context)

    @abstractmethod
    def get_data_info(self, index) -> dict[str, Any]: ...           # :106  YOU implement
```

### 一個真實的 `get_data_info`（`datamodule/nuscenes/detection3d.py:108`）

```python
def get_data_info(self, index):
    sample = self.data_infos[index]
    lidar_path = self._resolve_lidar_path(sample)
    return {
        "instances":   sample.get("instances", []),   # raw annotation records (NOT gt_boxes yet)
        "class_names": self.class_names,
        "name_mapping": self.name_mapping,
        "label_to_category": self.label_to_category,
        "sample_token": sample["token"],
        "timestamp":   sample.get("timestamp"),
        "lidar_path":  lidar_path,                     # a PATH — points are loaded by a transform
        "num_pts_feats": int(...),                     # feature width used to reshape the file
        "sweeps":      self._resolve_sweeps(sample),   # historical frame metadata
    }
```

請注意：`instances` 是*原始*紀錄（後續的 transform，也就是 `LoadAnnotations3D`，會把它們
轉換成 `gt_boxes`/`gt_labels`），而 `lidar_path` 是一個*路徑*（由 `LoadPointsFromMultiSweeps`
讀取）。dataset 的 `__init__` 中唯一的檔案 I/O，是呼叫一次 `pickle.load(ann_file)`
（`nuscenes/detection3d.py:65`）。

### `PipelineContext`（`datamodule/pipeline_context.py`）

會傳給每一個 transform。攜帶了 `dataset`、`index` 與一個 RNG，並提供
`sample_secondary(pre_transform)`，讓*混合型（mixing）* augmentation（例如 copy-paste、
FrustumMix）能夠取得另一個索引不同的 sample，而不會污染 sample dict。把編排
（orchestration）狀態排除在資料 dict 之外，是刻意的資訊隱藏（information hiding）
設計選擇。

## 3. `DataModule` — dataloader 與 collation（`datamodule/base.py:139`）

```python
class DataModule(L.LightningDataModule, ABC):
    def __init__(self,
                 collation_map=None,
                 train_transforms=None, val_transforms=None, test_transforms=None, predict_transforms=None,
                 train_dataloader_cfg=None, val_dataloader_cfg=None, test_dataloader_cfg=None, predict_dataloader_cfg=None):
        ...
        self.collation_map = dict(collation_map or {})
        if "offset" in self.collation_map:                           # :200
            raise ValueError("'offset' is a reserved collation key generated by concat inputs.")

    @abstractmethod
    def _create_dataset(self, split, dataset_transforms=None) -> Dataset: ...   # :249  YOU implement
```

### 子類別要實作什麼

幾乎什麼都不用做 — 只需要 `_create_dataset`。以下取自 NuScenes（`nuscenes/detection3d.py:181`）：

```python
def _create_dataset(self, split, dataset_transforms=None):
    return NuscenesDetection3DDataset(
        data_root=self.data_root,
        ann_file=self.ann_files[split],      # {"train":..., "val":..., "test":..., "predict":...}
        class_names=self.class_names,
        name_mapping=self.name_mapping,
        dataset_transforms=dataset_transforms,   # ← the split's transform pipeline, injected here
    )
```

### `setup()` 把 Lightning 的 stage 對應到各個 split（`base.py:268`）

```python
stage_splits = {"fit": ["train", "val"], "validate": ["val"], "test": ["test"], "predict": ["predict"]}
splits = ["train","val","test","predict"] if stage is None else stage_splits[stage]
for split in splits:
    transforms = getattr(self, f"{split}_transforms")   # the per-split TransformsCompose
    setattr(self, f"{split}_dataset", self._create_dataset(split, transforms))
```

所以呼叫 `trainer.fit(...)` 會觸發 `setup("fit")` → 建構 `train_dataset`（使用
`train_transforms`）與 `val_dataset`（使用 `val_transforms`）。

### Dataloader（`base.py:298`）

```python
def _create_dataloader(self, split):
    dataset = getattr(self, f"{split}_dataset")
    cfg = getattr(self, f"{split}_dataloader_cfg")       # a DataLoaderConfig
    return DataLoader(dataset=dataset, collate_fn=self.collate_fn, **cfg.to_dataloader_kwargs())
```

`DataLoaderConfig`（`base.py:40`）是一個 dataclass：`batch_size`、`num_workers`、
`pin_memory`、`persistent_workers`、`shuffle`、`drop_last`。`_coerce_dataloader_cfg`
接受 dataclass、一般的 dict，或是 Hydra 的 `DictConfig`，並將其正規化 — 這就是
「Hydra 邊界」，YAML 對映在此變成有型別（typed）的物件。注意當 `num_workers == 0` 時，
`persistent_workers` 會自動被強制關閉（`base.py:71`）。

> 有些 datamodule 會覆寫 `_create_dataloader` — 例如 T4 detection 會加入 repeat-factor
> frame sampling（`DistributedWeightedRandomSampler`），只針對 **train** split 做稀有
> 類別的重新平衡。NuScenes detection 則不會這麼做。

## 4. Collation — 組 batch 的引擎（`base.py:423`）

`collation_map` 是把一串逐 sample 的 dict 轉換成單一 batch dict 的合約（contract）。
它是一份**嚴格的白名單**：只有列在其中的 key 才會保留下來。

```python
def collate_fn(self, batch):
    result, primary_lengths, deferred_index_concat = {}, None, []
    for key, strategy in self.collation_map.items():
        missing = [i for i, s in enumerate(batch) if key not in s]
        if missing:
            logger.warning("Key '%s' declared but missing from samples %s. Skipping...", key, missing)
            continue                                            # :456  predict/deploy tolerate this
        values = [self._coerce_value(s[key]) for s in batch]    # numpy → tensor
        match strategy:
            case CollationStrategy.STACK:  result[key] = self._apply_stack(key, values)      # shapes must match
            case CollationStrategy.CONCAT:
                tensor, lengths = self._apply_concat(values)
                result[key] = tensor
                if primary_lengths is None:                     # first concat key = primary space
                    primary_lengths = lengths
                    result["offset"] = torch.cumsum(lengths, dim=0)   # :475
            case CollationStrategy.INDEX_CONCAT: deferred_index_concat.append((key, values))  # done after
            case CollationStrategy.LIST:   result[key] = list(values)
    ...
```

| 策略 | 用於 | 產生 |
| -------- | ---------- | -------- |
| `stack` | 形狀固定的 tensor（影像） | `(B, ...)` tensor；形狀不一致會丟出 `ValueError` |
| `concat` | 長度不一的點雲（PTv3） | 一條長 tensor ＋ `batch["offset"]`（累積長度） |
| `index_concat` | 指向 concat 之後點雲的逐點索引 | 索引會位移，在 concat 之後仍保持有效（需要一個 `concat` key） |
| `list` | 每個 sample 長度不一的資料（CenterPoint 的 points/boxes） | 原封不動的 Python list |

CenterPoint 的對映（來自它的 `base.yaml`）：

```yaml
collation_map: { points: list, gt_boxes: list, gt_labels: list }
```

它使用 `list` 是因為每個 sample 的點數不同，而 voxelize 被延後到 GPU 前處理階段才
進行。像 PTv3 這種以點為基礎（point-based）的模型，則改用 `concat`/`index_concat`，
並依賴 `batch["offset"]` 來還原每個 sample 的邊界。

**`_coerce_value` 的細節（`base.py:327`）：** numpy array 會轉換成連續（contiguous）
的 tensor；**numpy 純量（scalar）則會保留其 dtype** — 這就是為什麼 float64 的
epoch-second 時間戳記在 collation 之後不會被 float32 量化成約 256 秒一階的原因。
非數值型別的物件會原樣通過（因此 `list` 可以攜帶任意的 Python 物件）。

**`offset` 是保留字（reserved）** — 若在 `collation_map` 中宣告它，會在建構時丟出例外
（`base.py:200`）。

## 5. 兩套資料堆疊並存

這一點常讓讀程式碼的人感到意外，所以值得直接說清楚。目前存在**兩套獨立的資料
堆疊**：

| | 主要堆疊（以 dict 為基礎） | Multi-task／database 堆疊（有型別） |
| --- | --- | --- |
| 基底類別 | `datamodule/base.py` 的 `Dataset`/`DataModule` | `datamodule/multi_task/` + `databases/` |
| Sample 型別 | 一般 `dict` | Pydantic dataclass（`MultiTaskGTSample`） |
| Info 來源 | pickle 過的 `.pkl` info 檔 | `DatasetRecord` 的 Parquet 快取 |
| Collation | `DataModule.collate_fn` + `collation_map` | `MultiTaskGTBatch.collate_gt_samples`（padding） |
| 使用者 | CenterPoint、大多數在 NuScenes 與 T4 上的 detection/segmentation | multi-task／較新的 T4 流程 |

你會接觸到的大多數模型（CenterPoint、BEVFusion、StreamPETR、FRNet、PTv3）都是使用
搭配 `.pkl` info 檔的**主要堆疊**。database 堆疊則是較新、具型別的路徑。

## 6. `databases/` 層 — 離線資料集轉換成經過驗證的快取

`databases/` 是一個**離線前處理／快取層**，與 datamodule 是分開的。它的工作是：
透過 `t4-devkit` 解析一次原始的 T4/NuScenes 資料集，用 **Pydantic schema** 驗證，
並寫出以欄（columnar）儲存的 **Parquet 快取**，內容是一筆筆 `DatasetRecord`。

```text
raw T4 dataset (JSON tables)
   → T4RecordsGenerator (reads via t4-devkit, per sample)
   → T4SampleRecord.to_dataset_record()
   → DatasetRecord  (frozen, strict Pydantic model)
   → Polars DataFrame → Parquet (cached under a hash of the config)
```

關鍵檔案（`docs/databases/t4dataset.md` 有完整說明）：

| 路徑 | 角色 |
| ---- | ---- |
| `databases/base_database.py` | `BaseDatabase`：版本／路徑、`database_hash`（快取失效判斷）、載入輔助函式 |
| `databases/t4dataset/t4dataset.py` | `T4Dataset(BaseDatabase)`：跨情境（scenario）平行產生紀錄 |
| `databases/t4dataset/t4records_generator.py` | 讀取 T4 標註，擷取 lidar frame／sweep／box |
| `databases/schemas/dataset_schemas.py` | `DatasetRecord`、`DatasetTableSchema`（frozen Pydantic） |
| `databases/box3d_pipelines/` | 在建立快取時進行框（box）標籤重新對映／合併／速度裁剪（velocity clipping） |

**快取是以 config ＋ schema 的雜湊值（hash）作為鍵值**（`database_hash`），所以只要
變更類別名稱、label 對映或 schema，快取就會自動失效 — 這是天生（by construction）
就具備的可重現性（reproducibility）。

## 8. 交棒給模型（GPU 前處理）

在 collation 之後，Lightning 會把 batch 搬到 GPU 上，並呼叫模型的
`on_after_batch_transfer`，執行模型自有的 `DataPreprocessing`（`preprocessing/base.py`）：

```python
class DataPreprocessing:
    def __call__(self, batch):
        for layer in self.pipeline:
            batch |= layer(batch)          # dict-in/dict-out, on device
        return batch
```

以 CenterPoint 來說，唯一的 layer 是 `PointPillarPreprocessor`
（`preprocessing/detection3d/point_pillar.py`），它會對每個 sample 的 `points` 做
voxelize，並**新增** `voxels`、`num_points`、`voxel_coords`：

```python
for batch_index, points in enumerate(points_list):
    voxels, coords, num_points = hard_voxelize(points, voxel_size, point_cloud_range,
                                               self.max_num_points, self.max_voxels)
    batch_column = torch.full((coords.shape[0], 1), batch_index, ...)   # prepend batch idx
    coords = torch.cat([batch_column, coords], dim=1)                   # → [batch, z, y, x]
    ...
outputs["voxels"], outputs["num_points"], outputs["voxel_coords"] = ...
```

為什麼放在這裡而不是 CPU transform 中：voxelize 運算量大、適合在 GPU 上做，而且
*與模型相關*（grid 必須和模型相符）。這樣的拆分讓逐 sample 的 CPU augmentation 與
逐 batch 的 GPU 整形彼此獨立。更多說明請見 [../model/model_architecture.md](../model/model_architecture.md)。

## 端對端範例（NuScenes CenterPoint）

```text
NuscenesDetection3DDataset.__init__      pickle.load(nuscenes_infos_train.pkl)  → self.data_infos
  │
__getitem__(i)
  ├─ get_data_info(i)                     {instances, lidar_path, sweeps, class_names, ...}
  └─ apply_transforms(...)                train_transforms pipeline:
        LoadAnnotations3D                 instances → gt_boxes(N,9), gt_labels, gt_num_points
        LoadPointsFromMultiSweeps         lidar_path + sweeps → points (with time-lag col)
        RandomFlip3D / GlobalRotScaleTrans   augment points + boxes jointly
        PointsRangeFilter / ObjectRangeFilter   crop
        PointShuffle
  ▼ sample dict {points, gt_boxes, gt_labels, ...}
collate_fn (collation_map: points/gt_boxes/gt_labels = list)
  ▼ batch {points:[...], gt_boxes:[...], gt_labels:[...]}
── GPU ──
on_after_batch_transfer → PointPillarPreprocessor  → adds voxels, num_points, voxel_coords
  ▼ model.forward(voxels, num_points, voxel_coords)
```

## Common debugging cases

| 症狀 | 原因 | 修正 |
| ------- | ----- | --- |
| `forward`/`compute_metrics` 中某個 key 出現 `KeyError` | 不在 `collation_map` 中（被丟棄了） | 把它加進 `collation_map` |
| 出現「declared but missing from samples」警告 | 某個 transform 沒有產生它，或它是 predict 時的 train-only key | 在 predict/deploy 時屬於預期行為；否則要檢查該 transform |
| `stack` 出現 `ValueError: sample k has shape …` | 用 `stack` 去 collate 形狀不固定的 tensor | 把該 key 改成 `list` 或 `concat` |
| `index_concat requires a concat key` | 單獨使用了 `index_concat` | 加一個 `concat` key 來定義主要空間（primary space） |
| 時間戳記看起來被量化／四捨五入 | 數值精度流失 | 依賴 `_coerce_value` 保留 numpy 純量的 dtype；保持 float64 |
| lidar 路徑出現 `FileNotFoundError` | `data_root` / `AUTOWARE_ML_DATA_PATH` 設錯，或 info 中的路徑是相對路徑 | 檢查 `set_data_path.sh` 與 `datamodule.data_root` |
| 找不到 info 檔 `.pkl` | 沒有執行 `create-dataset`，或 `--out-dir` 不一致 | 重新產生；檢查 `train_ann_file` 的插值（interpolation） |
| 快取看起來過期（database 堆疊） | 其實沒有 — `database_hash` 會在 config/schema 變動時自動失效 | 只有在你改動了原始資料時才需要刪除／重建 |

## Common modification scenarios

| 我想要… | 這樣做 |
| ---------- | ------- |
| 新增一個 dataset | 繼承 `Dataset`（實作 `get_data_info`）＋ `DataModule`（實作 `_create_dataset`）；撰寫 task config。見 `docs/contributing/adding-models.md` |
| 新增一個模型需要的 key | 在 transform／preprocessing 中產生它，**並且**把它加進 `collation_map`，**並且**加上對應的 `forward` 參數 |
| 重新平衡稀有類別 | 使用／設定 repeat-factor 的 `train_frame_sampling`（T4 detection） |
| 改變每個 split 的 batch size／worker 數 | config 中的 `datamodule.<split>_dataloader_cfg` |
| 使用不同的點雲 batching 方案 | 改變 `collation_map` 中的策略（`list` ↔ `concat`/`index_concat`）並調整模型 |
| 保留 metadata 以利除錯 | 例如把 `sample_token: list` 加進 `collation_map` |
